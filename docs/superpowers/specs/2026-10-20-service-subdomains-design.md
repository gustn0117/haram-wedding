# 서비스별 서브도메인 사이트 설계

작성일: 2026-10-20

## 목적

포토부스·컨시어지·사회/축가를 각각 "별도 사업"처럼 보이는 전문 사이트로 분리한다.
본사 사이트(haramevent.kr)의 서비스 페이지는 짧은 소개와 전용 사이트로 가는 링크만 남긴다.

## 구조 결정

한 코드베이스에서 도메인으로 사이트를 가른다 (레포·컨테이너 추가 없음).

| 도메인 | 내용 |
| --- | --- |
| haramevent.kr | 본사 사이트. 서비스 페이지는 요약 + 전용 사이트 링크 |
| photobooth.haramevent.kr | 웨딩 포토부스 전문 사이트 |
| concierge.haramevent.kr | 예식 컨시어지 전문 사이트 |
| host.haramevent.kr | 예식사회자·축가 전문 사이트 |

`middleware.ts`가 호스트를 보고 `/sites/<slug>/...` 로 rewrite 한다. 주소창에는 서브도메인만 보인다.

## 사이트별로 분리되는 것

- 디자인 토큰(색·타이포)과 레이아웃. 공통 헤더/푸터를 쓰지 않는다.
- 메뉴 구성과 페이지 구성.
- robots.txt, sitemap.xml, canonical, OG, 구조화 데이터.

## 공유하는 것

- 서비스 사실 데이터(lib/services.ts) — 한 곳에서 고치면 모든 사이트에 반영.
- 문의 저장(Supabase)과 관리자 페이지. 문의에 어느 사이트에서 왔는지 기록한다.
- public/ 자산과 IndexNow 키 파일(같은 앱이 모든 호스트를 서빙하므로 자동 공유).

## 페이지 구성 (사이트당)

홈 / 서비스 상세 / 운영 방식 / 자주 묻는 질문 / 문의.
포트폴리오는 사진이 준비되면 추가한다.

## SEO

- 서브도메인은 검색엔진에 별개 사이트다. 색인은 0부터 시작한다.
- 각 사이트에 전용 sitemap을 두고 IndexNow로 색인 요청한다.
- 본사 사이트의 요약 페이지에서 전용 사이트로 링크해 연결을 만든다.
- 서치어드바이저 등록은 사이트마다 사용자가 직접 한다.

## 인프라

1. Cloudflare에 서브도메인 CNAME 추가 (API로 자동).
2. 서버 tunnel config에 호스트 추가 (ssh로 자동).
3. tunnel 재시작 — 사용자가 서버 터미널에서 직접 실행 (전체 사이트 중단 위험 때문).

## 작업 순서

포토부스를 먼저 완성해 확인받고, 같은 틀로 컨시어지와 사회/축가를 만든다.
